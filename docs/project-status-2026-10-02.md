## 当前目标与模型决策

当前优先验证环境概况和低延迟：大致场景、主要人物、显眼物体与姿态。
不要求识别杯中饮品等隐藏内容；导航建议不作为当前验收条件。
MiniCPM-V 4.6 / Ollama 继续为默认；SmolVLM-500M / llama.cpp CPU 保留为
未来 Plan B 或辅助候选，尚未接入自动切换或双模型流程。
小模型/OpenVINO 的速度优势伴随误判、猜测及部分输出截断，详见
[模型追加实测](smolvlm-openvino-evaluation-2026-09-30.md)。

## 已实现

- 离线 `report`、`ask`、单帧环境概况 `scene`。
- Windows 11 `camera`：OpenCV 摄像头采集、Tkinter 实时预览与后台 MiniCPM 分析。
- 手动分析及可选连续分析；完成后等待 2 秒再采最新帧，最多一个请求，不排队。
- 提交帧小图、结果文字、请求耗时及帧时间差，避免将旧帧描述误当成当前画面。
- 默认最长边 640 像素、96 输出 tokens；每次请求超时 60 秒，最多两次尝试。
- 默认不保存摄像头画面、视频或描述；使用本机 Ollama。关闭窗口/Esc 释放摄像头，
  已提交请求可能仍在 Ollama 服务端完成。未实现机器人控制。

摄像头 demo 是用户后续授权的范围扩展；原 Stage 1 离线接口继续保留。
“实时预览”不代表模型逐帧实时理解。

## 启动与真实测试

在项目目录运行，确保本机 Ollama 已运行且模型已安装：

```powershell
.venv\Scripts\python -m visualintel camera
```

默认设备 0、DirectShow。失败时检查 Windows 摄像头桌面应用权限及其他应用占用，
可尝试 `--index 1` 或 `--backend msmf`。`--max-image-side 320` 用于低分辨率对照。
点击“分析当前画面”，对照提交帧核对场景、人物、显眼物体、无依据猜测和耗时。
连续模式应检查预览是否持续更新、是否出现旧结果与新画面不一致；低光/遮挡也需验证。
