# 本地模型与结构化输出评估（2026-09-30）

## 评估方法与范围

本轮使用本机 Windows、Ollama 0.34.4，以及既有 11.93 秒人物动作视频。
同一帧/帧序列、问题和生成参数用于候选对照：temperature=0、seed=42，
输出有明确 token 上限。图像、原始响应、服务计时和验证错误均保存于
`outputs/model-evaluation/`，未覆盖此前报告。没有调用付费 API 或云 GPU。

补充照片为 COCO val2017 的 `000000000139.jpg`：可见电视、桌椅、厨房区域、
木地板与人物。图片仅留在 gitignore 的本地输出目录，未随仓库分发。
来源：[COCO](https://cocodataset.org/)，实际下载使用
[公开 S3 对象](https://s3.amazonaws.com/images.cocodataset.org/val2017/000000000139.jpg)。
原图片域名的 HTTPS 请求出现证书主机名不匹配；未关闭证书验证，改用 S3 HTTPS 地址。

质量结论来自助手对抽样帧/照片的视觉核对与原始回答审阅，**尚未经独立人工验收**。
语法校验自动化，语义判断未自动打分。样本少、场景有限，不能给出通用准确率。
首次加载和图片缓存影响耗时；表中是实际请求时长，不是稳态延迟排行榜。
模型身份、量化与输入 SHA-256 记录在各组 `metadata.json`。

## 已观察到的结果

| 检查项 | MiniCPM-V 4.6 | Ollama Moondream |
|---|---|---|
| 人物近景简短描述 | 描述人物、红衣、眼镜和手部动作，12.27 秒 | 漏掉主体人物，仅描述货架物品，23.00 秒 |
| 人物拿着什么（JSON） | 白色杯子，16.31 秒 | 杯子但猜测为咖啡，16.73 秒 |
| 杯中饮品不可见时是否拒绝猜测 | 回答无法确定，15.25 秒 | 猜测是水，3.08 秒 |
| 房间客观描述 | 正确列出电视、桌椅、厨房等主要可见内容，15.91 秒 | 包含部分物体，随后重复 table 直到截断，22.80 秒 |
| 房间建议（JSON） | 字段有效，但内容仍是指令语气，16.92 秒 | 声称 safe，随后重复数字至截断，14.83 秒；结构校验失败 |

Moondream 的这个发行版不适合作为默认替代：在本轮测试中存在明显漏描述、
无依据推断和重复退化。结论仅针对已测试的 Ollama 发行版，不代表整个
Moondream 系列或较新版本的能力。

### Qwen3-VL 2B Instruct 的追加结果

| 检查项 | 原图、固定贪心采样的实际结果 |
|---|---|
| 人物近景描述 | 主体描述正确，个别背景物品解释未确认；104.45 秒，含约 8.99 秒加载 |
| 人物拿着什么 | 回答 cup；51.58 秒 |
| 杯中内容不可见 | 正确回答无法确定；3.47 秒，该图片已在上一个请求使用，存在缓存影响 |
| 三帧 JSON 报告 | 字段与异常标记一致，动作时间线较完整；26.42 秒；图片已在文本报告使用 |
| 近景是否足以判断路线 | 正确说明证据不足；12.64 秒，同样存在缓存影响 |
| 房间描述 | 正确包含电视、餐桌、木地板及人物等主要内容；53.89 秒 |
| 房间建议 | 输出重复并截断，18.61 秒，结构校验失败 |

三帧报告虽通过结构校验，仍把杯子用途说得过于确定，或给出并无证据的
“保持温暖”等推断；路线不可见时未稳定按提示词给出 low confidence。
这些是内容问题，不会因为 JSON 有效就被当作质量通过。

官方 Instruct 采样设置的三个补测均通过结构校验：不可见饮品 2.86 秒、
三帧报告 26.77 秒、房间建议 9.52 秒。此次没有重复退化，但房间建议仍有
“Ensure …” 等指令句，报告也仍有无依据推断。此时图片已反复使用，不能
将这些数字作为新图延迟或稳定速度排名。

### 缩图实验：本轮不启用为默认优化

将最长边降到 320 像素，保留纵横比、不放大小图；使用官方 Instruct 采样
设置完成六个实际测试。单帧事实问题的 input token 仍为 **1,065**，房间
描述仍为 **1,110**，三帧 JSON 报告仍为 **3,449**，与原图对应请求一致。
因此，本轮没有证明“缩小 JPEG 就能减少这套 Ollama 路径的视觉 token”。

缩图后的单帧事实问题 48.03 秒，对应原图 51.58 秒，仅单次对照、且采样
设置不同，不能据此宣布有效提速；三帧报告 135.92 秒，原图的快速结果则
包含已用图片的缓存影响。它们不能直接算加速比。缩图还可能损失细节。
缩图仅留在评估工具，通过 `--max-image-side` 显式试验；生产默认没有缩图。

### 最终取舍

**保留 MiniCPM-V 4.6 默认底座。** 在现有 CPU 硬件、有限样本和成本约束下，
未找到在质量、延迟、格式稳定性与建议可靠性上都值得直接替换它的候选。
Moondream 旧发行版不推荐接入；Qwen Instruct 可用于后续研究，但在本轮
仍更慢、有重复退化或建议内容缺陷，未设为默认，也未声称它全面优于当前模型。

本轮落实的是工程可靠性改进与可复现实测工具，尚未解决通用场景理解或
导航安全问题。后续质量验收需要更多真实场景与独立人工标注，不能仅靠
继续堆提示词或正则规则来保证正确。

### 当前模型的结构化改进

- 同样三帧的旧文本报告用时 49.78 秒，将普通拿杯动作标为异常，漏了
  UNUSUAL_NOTE，confidence 包含额外文本，建议是指令句。
- 首轮 JSON Schema 报告用时 55.39 秒，字段与类型有效，异常标记正确为
  false，但仍提出缺乏依据的杯子卫生建议。**JSON 正确不等于内容正确**。
- 更严格提示词的另一轮三帧报告用时 46.45 秒，却出现 false 异常标记与
  非空说明矛盾；验证器拒绝该结果。不能声称提示词修改总能改善模型表现。
- 实际生产流程使用六帧生成报告成功，92.14 秒；指令建议被暂扣，保留
  动作描述与固定免责声明。
- 八帧事实问答成功，117.73 秒，简短回答且无 guidance；此前未限制输出
  的相同问题为 209.47 秒。此单次差异包含提示词、输出长度与缓存变化，
  不作为稳定加速比例。
- 八帧建议问答成功，119.16 秒，固定免责声明存在。但它把“没看到路线”
  推断成“没有路线”，仍是语义质量问题，未认定导航建议通过。

## 已落实的工程改进

- 报告、事实问答、建议问答分别使用 JSON Schema；验证字段、类型、枚举、
  异常标记与说明的一致性，不再依赖模型拼写文本字段标题。
- 无效结构或 token 截断触发一次重试；格式校验失败时，重试提示词包含
  修复要求，避免仅重复同一个不合格输出。仍失败则明确记录失败。
- 输出长度受限，默认 temperature=0，提示词禁止猜测距离、未见动作和路线。
- `ask --question-mode factual/advice` 可覆盖自动关键词分类；求建议时即使
  模型遗漏标记，也由代码添加免责声明。
- 扩展明显指令句拦截，覆盖逗号后的条件式指令。该规则不是完整语义校验。
- 报告文件使用独占创建，避免并发时旧文件存在性检查过期后仍被覆盖。
- 保留原文本解析能力及原报告，维持报告 JSON schema 与命令的兼容性。
- 自动化测试目前 **83 项通过**。未增加新的包依赖；图像实验使用 OpenCV
  及其已安装的 NumPy 依赖，其余为 Python 标准库。

## 候选适用性与项目健康

- [Ollama Moondream](https://ollama.com/library/moondream) 的测试发行版约 1.7GB，
  页面显示较旧；[官方模型卡](https://huggingface.co/vikhyatk/moondream2) 标记
  Apache-2.0，并明确有较新预览版本。官方 GitHub API 本轮查询的最新提交为
  2026-04-20；最近 issue 仍有活动，但未全面审计所有关键问题。
  分类：**旧发行版仅用于学习/对照测试，本项目不建议部署为默认底座**。
- [Qwen3-VL 2B](https://ollama.com/library/qwen3-vl:2b) 的 Ollama 包约 1.9GB，
  Apache-2.0，现有服务版本满足其要求；
  [官方模型卡](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct) 与
  [官方仓库](https://github.com/QwenLM/Qwen3-VL) 支持图像/视频任务。
  GitHub API 本轮查询的最新提交为 2026-01-30，近期仍有 issue 活动。
  只使用 Ollama 官方模型包，未执行仓库的安装脚本或自定义远程代码。
  本地实测后未更换默认模型，不以模型宣传或 star 数下结论。
  本项目集成分类：**有潜力但仍需实验验证**。

### Qwen 标签选择修正

首次使用不明确的 `qwen3-vl:2b` 标签，随后发现它与
`qwen3-vl:2b-thinking` 指向同一摘要。请求 `think:false` 仍产生额外 thinking
字段，单帧描述 61.56 秒，三帧文本报告 172.50 秒；该组测试在六个已完成
案例后结束，原始记录保留，未关闭 Ollama 服务。
这组结果不能当作 Instruct 版结论。

后续使用明确的 `qwen3-vl:2b-instruct`，并补充官方 Instruct 采样设置的
独立对照。[官方标签](https://ollama.com/library/qwen3-vl/tags) 区分了两个版本；
[官方模型卡](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct) 的 VL 参数为
非贪心采样、temperature=0.7、top_p=0.8、top_k=20、presence_penalty=1.5。
该对照使用固定 seed 与有限输出长度，不完全等同于官方长输出评测。
评估脚本会拒绝对不明确的 Thinking 标签套用 Instruct 参数。

## 复现与限制

```powershell
.venv\Scripts\python scripts/evaluate_models.py --model minicpm-v4.6 --output outputs/compare-new --improved-prompt
.venv\Scripts\python scripts/evaluate_models.py --model moondream --output outputs/moondream-new --single-image-only
```

`--extra-image` 可加入另一张图片；`--cases` 可只执行指定案例。
`--vendor-sampling` 仅允许明确的 Qwen Instruct 标签；`--max-image-side 320`
可复现缩图实验。生产 CLI 本轮仍使用已验证的 MiniCPM 默认生成配置，
没有自动套用实验采样配置或更换模型。
输出目录必须是新目录，工具不会覆盖历史记录。评估脚本不自动重试，便于
看到单次原始失败；生产引擎重试一次，两者耗时不可混为一谈。

本轮没有新录制实际绕行障碍视频，也没有做多场景长视频评测、重复统计或
完整安全评估。格式和失败处理已有改进，仍不能将输出用于无人监督的行动。
